# Прогресс обучения

## Цели обучения

- Освоить Codex в IntelliJ IDEA с нуля и пройти цикл работы агента от исследования репозитория и согласования плана до реализации и проверки.
- Подготовиться к собеседованию Java Tech Lead на примере Customer Service. На первом этапе разобрать настройку JDK, жизненный цикл Maven и проверку Spring Boot приложения.

## Технологический стек

- Java 21 и Maven. На прежнем macOS-окружении использовали Homebrew OpenJDK 21.0.13.1 и Maven 3.10.2.
- Spring Boot 3.5.16, Spring Web и Spring Data JPA.
- H2 в памяти и JUnit 5 через `spring-boot-starter-test`.

## Пройденные этапы

1. Исследовали содержимое репозитория, состояние Git и ограничения Codex.
2. Проверили Java и Maven, нашли Homebrew JDK 21 и подтвердили его использование Maven через переменные окружения одной команды.
3. Согласовали структуру проекта, зависимости, правила `.gitignore` и порядок проверки.
4. Создали минимальный каркас и выполнили первую попытку `mvn -o verify`.
5. Провели независимое ревью POM, структуры, Java-кода, теста, `.gitignore` и документации. Замечаний уровней Critical, Major и Minor не было. Единственное предложение выполнили: добавили в конспект команды для запуска Maven с Homebrew JDK 21 и подтвердили выбор JDK через `mvn -version`.
6. Проверили загрузку и область действия `AGENTS.md`, приоритет `AGENTS.override.md` и разрешение конфликта на примере Lombok. Подготовили три файла инструкций и зафиксировали результаты в [конспекте второго занятия](training/lesson-02.md).
7. Завершили занятие Context Management. Измерили расход Context Window и проверили изоляцию сессий, Context Compaction и Session Handoff. Результаты записали в [конспекте третьего занятия](training/lesson-03.md).
8. Завершили проверку работоспособности проекта на Windows 11. Результаты внесли в [конспект первого занятия](training/lesson-01.md#проверка-на-windows-11).

## Текущее состояние проекта

Работу перенесли на личный ноутбук с Windows. Основной инструмент обучения — Codex в IntelliJ IDEA, дополнительный — Codex CLI.

Инструкции для Codex распределены между [корнем проекта](AGENTS.md), [production-кодом](src/main/AGENTS.md) и [тестами](src/test/AGENTS.md). Зафиксировали приоритет вложенных инструкций, порядок запуска `mvn verify` на JDK 21 и правила работы с входными и персональными данными. Изменение оформлено коммитом `docs: define scoped agent instructions`. Поскольку изменились только Markdown-файлы, `mvn verify` для этого коммита не запускали.

В репозитории есть `pom.xml`, `.gitignore`, точка входа Spring Boot и один тест `contextLoads` с `@SpringBootTest`. Бизнес-логика ещё не реализована.

## Результат проверки на Windows

- `java` и `javac` показали Eclipse Temurin 21.0.13.1. Maven 3.9.16 из IntelliJ IDEA использовал тот же JDK. После проверки каталог отдельной установки Maven 3.9.16 добавили в пользовательский `PATH` и подтвердили работу `mvn -version` с JDK 21 в новом процессе PowerShell.
- Sandbox заблокировал загрузку родительского POM Spring Boot 3.5.16 из Maven Central. После предоставления доступа повторный `mvn verify` завершился с `BUILD SUCCESS`. Тест `contextLoads` прошёл, ошибок и пропусков нет.
- Собрали `target/customer-service-0.0.1-SNAPSHOT.jar` и запустили его. Spring Boot 3.5.16 подтвердил старт приложения, Tomcat 10.1.55 поднялся на HTTP-порту `8080`. Логи подтвердили штатную остановку Tomcat и HikariCP, процесс завершился с кодом `0`.
