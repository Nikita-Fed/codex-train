3. Выяснить, почему shell и Maven используют Java 25, и найти способ запускать Maven на JDK 21 без изменения глобальных настроек.
4. После согласования создать каркас без бизнес-логики, выполнить `mvn verify` на JDK 21 и сообщить фактические результаты.

## Проблемы и решения

| Проблема | Решение или статус |
|---|---|
| Сначала `mvn` отсутствовал в `PATH`. | После установки пользователем команда подтвердила Maven 3.10.2. |
| Shell и Maven продолжали использовать Java 25. | В `PATH` раньше стоял каталог Java 25, и `JAVA_HOME` указывал на тот же JDK. Для отдельного запуска Maven агент задал `JAVA_HOME` на Homebrew JDK 21 и добавил его `bin` в начало `PATH` только для этой команды. |

| Maven не смог создать каталог блокировок в пользовательском кэше. | Проверка остановлена. Предстоит согласовать работу с кэшем в рамках разрешений workspace. |

### Запуск Maven с Homebrew JDK 21

Выполните команды из корня проекта. Переменная `jdk21` содержит путь к установленному через Homebrew JDK. Подстановки `JAVA_HOME` и `PATH` действуют только для соответствующего запуска Maven.

```bash
jdk21="$(brew --prefix openjdk@21)/libexec/openjdk.jdk/Contents/Home"
JAVA_HOME="$jdk21" PATH="$jdk21/bin:$PATH" mvn -version
```

Убедитесь, что в строке `Java version:` указана версия `21.x`, затем запустите сборку:

```bash
JAVA_HOME="$jdk21" PATH="$jdk21/bin:$PATH" mvn -o verify
```

## Проверка на Windows 11

28 ноября 2026 года завершили проверку работоспособности проекта на личном ноутбуке.

| Шаг | Фактический результат |
|---|---|
| `java -version` и `javac -version` | Eclipse Temurin 21.0.13.1. |
| `mvn -version` | Maven 3.9.16 из IntelliJ IDEA использовал Eclipse Adoptium JDK 21.0.13.1. |
| `mvn verify` | `BUILD SUCCESS` после предоставления доступа к Maven Central и локальному Maven-кэшу. Тест `contextLoads` прошёл, ошибок и пропусков нет. |
| Проверка JAR | `target/customer-service-0.0.1-SNAPSHOT.jar`, 54 142 890 байт. |
| `java -jar target/customer-service-0.0.1-SNAPSHOT.jar` | Spring Boot 3.5.16 подтвердил запуск приложения за 12,49 секунды. Встроенный Tomcat 10.1.55 запустился на HTTP-порту `8080`. |
| Остановка | Spring Boot записал `Graceful shutdown complete`, JPA и пул HikariCP закрылись, процесс завершился с кодом `0`. |

- Изначально `mvn` отсутствовал в `PATH`. Для сборки запустили `mvn.cmd` из IntelliJ IDEA по полному пути. Затем добавили каталог отдельной установки Maven 3.9.16 в пользовательский `PATH` Windows и проверили `mvn -version` в новом процессе PowerShell.
- Первая попытка сборки остановилась до компиляции. Sandbox запретил подключение к Maven Central при загрузке `spring-boot-starter-parent:3.5.16` с ошибкой `Permission denied: getsockopt`. После предоставления доступа повторная сборка загрузила нужные артефакты и прошла без изменений в `pom.xml`.
- Терминал не передал `Ctrl+C` процессу Java. Временный Java-агент вызвал `System.exit(0)`, который запустил штатное завершение Spring Boot. После проверки временные файлы удалили.
