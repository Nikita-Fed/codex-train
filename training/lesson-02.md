# Занятие 2. Проектные инструкции AGENTS.md

## Цель

Проверить в Codex для IntelliJ IDEA, когда проектные инструкции появляются в контексте и как разрешать конфликты между правилами разных каталогов.

## Результаты экспериментов

| Эксперимент | Что наблюдали |
|---|---|
| Новая сессия | Корневой `AGENTS.md` загрузился автоматически. Требование к началу ответа сработало без просьбы прочитать файл. |
| Новый файл в открытой сессии | Инструкции из добавленного файла автоматически не применились в уже открытой сессии. |
| Ручное перечитывание | После явной просьбы агент прочитал инструкции с диска и применил их в текущей сессии. |
| Вложенные инструкции | При явном обходе каталогов по пути к целевым файлам агент обнаружил `src/main/AGENTS.md` и `src/test/AGENTS.md`. |
| `AGENTS.override.md` | В эксперименте файл `AGENTS.override.md` получил приоритет над `AGENTS.md` из того же каталога. |
| Конфликт Lombok при автоматическом применении | Корневое правило требовало использовать Lombok, а вложенное правило для production-кода запрещало его. Автоматическое разрешение дало ошибку. Агент опирался на корневое требование, пропустив более специфичное правило. |
| Конфликт Lombok после явного обнаружения | После чтения вложенного файла агент применил более специфичное правило для `src/main`. В итоговом наборе правила больше не конфликтуют. `pom.xml` не содержит Lombok, поэтому конструкторы пишутся явно. |
| Итоговый набор правил | Общий workflow и поиск инструкций закрепили в корне, правила Java/Spring production-кода в `src/main`, правила тестирования в `src/test`. |

## Рабочий порядок

Перед правкой проверь инструкции в каждом каталоге от корня до целевого файла. В одном каталоге выбирай `AGENTS.override.md`, если он есть. При конфликте между каталогами применяй более специфичное правило. Если инструкция появилась или изменилась во время текущей сессии, перечитай её с диска перед продолжением работы.
